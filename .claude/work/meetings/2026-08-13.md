## #53 — Documentation edits move to a per-owner queue

**Status: Decide.** *Unblocked by #50. Contradicts a `CLAUDE.md` bullet one day old.*

The proposal: stop editing `documentation/` inside every task's PR. A task that invalidates
something the site says appends an entry to a queue file naming what is now false and what it
should say, and the site is corrected in **one sweep** as its own task. The cost is measured, not
theoretical — GitHub #27, a three-hour issue about a return type, touched ten HTML files, and the
second pass still found two pages claiming the convergence log never reaches Python plus ~45
shifted `src` line references. Queues are **per-owner** (`documentation/mdube_edits.md` exists;
`jsargant_edits.md` was created on James's behalf, empty, marked not-yet-agreed) because a queue
is a churn list where entries are deleted once applied, and `merge=union` cannot express a
deletion. The cost that must be written into whatever we agree: **a sweep reads every queue file,
not only its own**, or a page owed edits by both owners gets half-corrected and looks deliberate.
Deleting `jsargant_edits.md` is the whole of the rejection.

**Q1. Do documentation edits move to a per-owner queue and a batched sweep?**
- **(a) Yes, per-owner queues** — `mdube_edits.md` / `jsargant_edits.md`, sweep reads both.
- **(b) No** — keep editing `documentation/` in the task's own PR. Delete `jsargant_edits.md`.
- **(c) Yes, but one shared queue file** — accepting that union merge cannot express a deletion,
  so applied entries must be struck through rather than removed.

**Q2. If yes — who owns the sweep, and when does it fire?**
- **(a) Whoever's queue is longest, whenever either queue passes a threshold**
- **(b) A standing task, alternating owners, one sweep per meeting cycle**
- **(c) Ad hoc — raise a `collab.md` item when a sweep is wanted**

### Decisions & doc changes

**Decided:** Documentation edits move to **per-owner queues**, confirming `documentation/mdube_edits.md`
and `jsargant_edits.md`. An entry has a three-stage life: raised by the task that invalidated the
page; **tagged `edited — please verify`** by whoever ran the sweep that applied it; **deleted by the
queue's owner** once they have checked the page says what they meant. The sweeper is not the
verifier, because the person who knows what the page should say is the one who raised the entry —
the same reason `[x]` means *you* saw it verified. The sweep is a standing task on an alternating
owner, one per meeting cycle, and **it reads every queue file, not only its own**, or a page owed
edits by both gets half-corrected and looks deliberate.

- `documentation/mdube_edits.md`, `documentation/jsargant_edits.md` — confirmed as the two queues;
  `jsargant_edits.md` loses its "not yet agreed" marker.
- `.claude/CLAUDE.md` — new bullet replacing the de-badging rule: a task that invalidates the site
  appends to its owner's queue instead of editing `documentation/`. States the three stages, that
  only the owner deletes an entry, and that a sweep reads both queues.
- `.claude/CLAUDE.md` — the sweep recorded as a standing alternating task, one per meeting cycle.
- **Queue entry format** — must carry what is now false, what it should say, and the page; gains an

  queues stay per-owner and never take `merge=union`.

- **(b) No** — the builder demonstrates the *API*, the TOML demonstrates the *science*.

## #61 — `set_base_graph`'s node-count check does not catch the failure it was written to prevent

**Status: Decide.** *Either answer amends §8; blocks GitHub #28 / `jsargant_set_base_graph`.*

all no-ops when preconditions fail, so a fallible `set_edge` becomes an error path in all nine; the
asymmetry between engine-generated indices and caller-supplied data is the point. The same argument
already decided the cap check (`decisions.md` 2026-08-12: `set_edge` clamps, so `set_base_graph`

  reproduces the exact failure §8 names.

**Q2. Self-loops — this model has none, so what should `set_base_graph` do with one?**

- **(b) Drop them, but say so** — documented as intended semantics rather than an accident.
- **(c) Keep dropping silently** — status quo; the thing #61 objects to.

### Decisions & doc changes
