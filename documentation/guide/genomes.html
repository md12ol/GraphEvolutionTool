How it works

Genomes

A genome is a compact recipe that expresses into a graph. GET ships two, and they are genuinely different ideas about how to describe a network — one edits an existing graph, the other writes one from nothing.

Why not just evolve the graph directly?

You could store a 100-node graph as its 4,950 possible edges and mutate those bits. It works, but it explores badly: a random bit-flip is almost always a tiny local change, and there is no structure a crossover can meaningfully recombine. Both of GET's representations are indirect encodings — small objects whose local changes produce structured, sometimes large, changes in the resulting graph.

They stack. Because a run returns (u, v, multiplicity) triples and an edge-edit run starts from a graph, you can evolve a topology with SDA and then refine it with edge-edit, with no new data format in between. See supplying a base graph.

The contract both satisfy

pub trait Genome: Clone + Send + Sync {
    type Context: Send + Sync;
    fn express(&self, context: &Self::Context) -> Graph;
    fn crossover<R: Rng + ?Sized>(&mut self, other: &mut Self, rng: &mut R);
    fn mutate<R: Rng + ?Sized>(&mut self, rng: &mut R);
    fn print(&self) -> String;
}

Four things to notice, because each one is load-bearing:

  • crossover recombines in place, leaving one child in each parent. It inherently produces two children, and an engine that kept only one would waste half of every crossover.
  • mutate applies exactly one mutation per call. This is a trait-level contract, not a per-representation choice — see Crossover & Mutation for why.
  • print is the type-erasure hook. It lets the non-generic Python entry point record which individual won without knowing its representation.
  • Context carries run-level configuration and is the authority on graph size and edge cap. It is shared by reference across every worker during expression, which is why it must be Send + Sync.

Edge-edit — a script over a base graph

An edge-edit genome is a list of encoded operations: "add an edge between these two vertices", "delete that one", "rewire this pair". Expression clones the base graph and applies every gene in order.

It is a script, not a graph. The same genome expressed against a different base graph gives a different result. That is the point of the representation — it encodes a transformation, which is what makes it good at refinement.

How a gene is packed

Each gene is a single 64-bit integer: an opcode in the low 4 bits and a 32-bit payload above it. Expression decodes the payload mixed-radix into four vertex parameters, using the node count n as the base: 

v1 = payload % n
v2 = payload / n   % n
v3 = payload / n²  % n
v4 = payload / n³  % n

Different operations use different numbers of those four. Nothing is validated: a decoded pair that names a self-loop or an impossible edit simply does nothing, because the graph ignores those silently.

The payload cannot address the whole space evenly, and this is inherited deliberately. Four base-n digits need n⁴ values but the payload has only 32 bits. At n = 1000 the fourth parameter only ever takes values 0..=4; at n = 257 it never exceeds 252. The bias comes from the legacy implementation GET reproduces, and it is pinned by a test — but it means the fourth vertex parameter of an operation is far from uniform on large networks.

The nine operations

All of them are no-ops when their preconditions fail. Nothing errors, nothing is retried.

OperationDoes
Add / Delete Add or remove one edge copy between v1 and v2.
Toggle Absent → add. At the cap → remove. Otherwise v3's parity decides.
LocalAdd / LocalDelete / LocalToggle The same three, but the far endpoint is reached by a two-hop walk from v1 — to neighbour v2, then to its neighbour v3. A walk that returns to the start, or passes through a degree-1 node, is rejected.
Hop Move an edge: connect v1 to its two-hop endpoint, then drop the edge to the intermediate neighbour — but only if the new edge actually took.
Swap A 2-opt rewire. Given two non-adjacent vertices of degree > 2 and one neighbour each, cut both edges and cross-connect — only if all four vertices are distinct and none of the would-be edges already exists. Needs at least 4 nodes.
Null A deliberate no-op. Weight it to 0 to make every gene do something.

Exact preconditions, and precisely how each one fails, are on the operations reference page.

Five of the nine are inert on an empty base graph. Swap, Hop and the three Local* operations all need existing structure to walk. A from-scratch edge-edit run therefore appears to do nothing until Add and Toggle have built something. This is self-correcting and is not a bug — but if you are watching an early log wondering why nothing is happening, this is why.

Operation weights

The nine operations are drawn from a weighted mix you set in config. The weights are relative, not percentages — they need not sum to anything. 0.0 disables an operation outright, and at least one must be positive.

They are validated once at startup and compiled into a prebuilt sampler that the whole population shares by pointer, rather than each individual carrying a copy. Two benefits: a weight error surfaces from config rather than mid-run, and sampling costs nothing per gene.

Crossover

Two-point, over genes. Draw a segment within the shorter genome's length and swap it. A genome shorter than two genes is left alone.

SDA — an automaton that writes a graph

A Self-Driving Automaton is a small finite-state machine. It has states, and for each (state, character) pair it knows two things: which state to move to, and which characters to emit. What makes it self-driving is that it reads back its own output as the tape that drives it.

It carries three pieces of data:

PieceIs
init_charThe first character, which starts everything.
transition table[state][char] → next state
response table[state][char] → a short list of characters to emit

How the graph comes out

Expression emits one character per upper-triangle vertex pair, and each character's raw value is that edge's weight. That is the whole mapping — there is no decoding step.

  • Output length is n(n-1)/2, one per pair.
  • Index i maps onto the i-th pair in row-major order — (0,1), (0,2), …, (0,n-1), (1,2), … — the same order get_edge_list uses.
  • So output[0] is init_char, and the initial character directly sets edge (0,1).
  • The run starts in init_state and consumes its own output as the driving tape: the character at the read head selects a transition, that transition's response is appended (truncated if it would overshoot), the state advances, and the head moves on.
  • Every response is at least one character long, so the output always grows and the run always terminates. No step cap is needed.
  • Fewer than two nodes yields an empty graph without running the automaton at all.

The alphabet is derived, not configured

num_chars = max_edge_multiplicity + 1. So the characters are exactly 0..=cap, and every character is a legal edge weight the graph will never clamp. There is no num_chars config key, and that is deliberate — it closes two silent failures:

  • An alphabet larger than the cap biases the graph toward the cap, as surplus characters clamp down onto it.
  • An alphabet smaller than the cap makes the upper weights unreachable, quietly exploring less space than you configured.

Unweighted (cap = 1) gives a binary alphabet that reads as absent/present, which is the common case. The consequence for validation is that 1 ≤ max_edge_multiplicity ≤ 255: 0 would give a one-character alphabet and a permanently empty graph, and 256 exceeds the storage the response table uses.

This invariant holds by convention, not by type. The dispatch layer always derives the alphabet from the cap, but the underlying constructor still accepts an arbitrary num_chars, and expression does not check a genome's alphabet against its context's cap. If you assemble a population by hand via the Rust route, you can silently reintroduce exactly the clamping bias this design exists to prevent.

init_state is configuration, not genome data

It lives on the run context rather than in the genome, because mutation and crossover never touch it. It must be < num_states: expression indexes the response table with it, so an out-of-range value would panic. Note that graphs of two nodes never run the loop at all, so this particular bug hides at small sizes.

Crossover

Two-point over states — swap a contiguous band of states, transitions and responses together. Swapping state 0 also swaps init_char, since together they determine the automaton's first transition.
