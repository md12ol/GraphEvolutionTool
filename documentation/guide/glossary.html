Glossary

Short definitions, each linking to the page that explains it properly. If a term on another page made no sense, it is probably here.

Evolutionary algorithm terms

TermMeans
Genome A compact recipe for a graph. GET has two kinds — an edit script and an automaton. Genomes
Expression Turning a genome into an actual graph. Always deterministic: the same genome and context give the same graph, every time.
IndividualOne genome in the population.
Population The whole set of individuals GET is working on. Its size is fixed for the run.
Generation One full round of the generational strategy: score everyone, then build a new population. Generational
Mating event One round of the steady-state strategy: draw a tournament, breed its two best, replace its two worst. Steady-state
Generation equivalent population_size mating events — the interval at which steady-state logs a row, so its history is comparable with a generational one.
Selection Choosing which individuals get to be parents. GET uses tournament selection.
Tournament Draw tournament_size individuals at random; the best one wins. Larger tournaments mean stronger pressure.
Selection pressure How strongly the algorithm favours better individuals. Too little and it wanders; too much and it converges on the first decent thing it finds.
Crossover Combining two parents into two children. GET's crossover works in place and always keeps both children. Crossover & Mutation
Mutation A small random change to one individual. GET applies exactly one per call, and the engine decides how many calls. Crossover & mutation
Elitism Copying the best individuals into the next generation unchanged, so progress cannot be lost. elite_count controls it under generational; steady-state gets it structurally.
Fitness The single number that says how good a graph is. Fitness & Orientation
Objective The function that computes fitness. Used interchangeably with "fitness function" here.
Convergence The population becoming similar and the fitness levelling off. GET does not detect it — runs are fixed-length by design.

GET-specific terms

TermMeans
Engine orientation The rule that inside GET, lower fitness is always better, whatever your objective does. Selection, elitism and replacement all assume it. Fitness & Orientation
Your units Whatever your objective naturally returns — infected nodes, an RMSE, anything. Nothing is normalized or sign-flipped for you, and this is what you get back at the Python boundary.
Direction Whether an objective is to be maximized or minimized. A property of the objective, and never a config field.
Orientation / orienting The negation that converts between your units and engine orientation. It happens exactly twice per run, at the two edges.
Context Run-level configuration a genome needs in order to express — graph size, edge cap, and anything mutation never touches. Shared by reference across every worker.
Dispatch The layer that turns a validated config into concrete types, builds the starting population, and runs the evolution. The Pipeline
Erasure Discarding a static type so a non-generic function can return the result. The objective is erased before dispatch; the genome type is erased before the outcome crosses into Python.
Replicate One of n runs at identical parameters and different seeds. The unit research actually reports. Seeds & Reproducibility
Master seed The single number that reproduces an entire experiment. Everything derives from it.
Provenance document The generated TOML — the exact document Rust parsed. Written beside your results, it re-runs the experiment verbatim.
Base graph The starting graph an edge-edit genome edits. Either data you bring or the output of a previous run. Python API
Stacking Feeding one run's output network in as the next run's base graph — typically evolve a topology with SDA, then refine it with edge-edit.

Graph terms

TermMeans
Multigraph A graph where a pair of nodes can be joined by more than one edge. GET stores that as a weight. The Graph
Edge multiplicity How many parallel edges join a pair — the "weight". 0 means no edge.
Edge cap max_edge_multiplicity: the largest weight allowed. 1 makes an ordinary simple graph, which is the default.
Degree How many distinct neighbours a node has. On a multigraph this differs from the number of edge copies at that node.
Upper triangle The pairs (u, v) with u < v — each edge counted once. The order SDA writes in and the order a run returns edges in.
Two-hop walk Step from a node to a neighbour, then to one of its neighbours. How the Local* and Hop edit operations find their far endpoint.
2-opt rewire Cut two existing edges and reconnect the four endpoints the other way round. What Swap does.

Epidemic terms

TermMeans
SIR Susceptible → Infectious → Recovered: the three states a node moves through, in that order, never backwards. The SIR Model
Patient zero The node the outbreak starts at. Pin it, or let a fresh one be drawn per epidemic.
SpreadHow many nodes were ever infected, including patient zero.
Length How many timesteps the epidemic occupied, including the final one where the last infectious node recovers without transmitting.
Profile The count of newly infected nodes at each timestep. Always starts at 1 and always ends in a terminating 0.
BurnoutThe point where no infectious nodes remain and the epidemic ends.
Re-roll Discarding an outbreak that was too short and simulating again — because a fizzled outbreak reports the dice, not the network. The re-roll
RMSE Root-mean-square error: the average size of the gap between two curves. What epi_prof_match minimizes.

Randomness terms

TermMeans
Common random numbers (CRN) Giving every candidate the same random draws so differences between them reflect the candidates rather than the dice. Essential when the objective is noisy. Seeds & Reproducibility
Seed stream Seeding one generator and using its output as a list of seeds. It is what makes run i's seed independent of how many runs you asked for.
Position-indexed seeding Deriving a seed from an index rather than by drawing sequentially — which is what keeps the epidemic re-roll from desynchronising a batch.
Stale fitness A recorded score computed under different dice than the individuals it is being compared against. An accepted limitation of steady-state.
Biased resample What the epidemic re-roll is: it shifts expected fitness upward rather than merely reducing variance, so it is not interchangeable with raising num_epidemics.
