Getting started

Build the module, write a config, run an evolution, read the result. Fifteen minutes, assuming you have a Rust toolchain.

1. Build the extension module

GET is a Rust crate compiled into a Python extension module. You need a Rust toolchain and maturin: 

# from the repository root
pip install maturin

maturin develop        # build and install into the current virtualenv, for development
# or
pip install .          # a normal install

Check it worked:

import get
print(get.Config)      # <class 'builtins.Config'>
Working on the Rust itself? Note that cargo test and the Python build need different feature flags — the extension-module feature is enabled by pyproject.toml at build time and deliberately not by the crate's own manifest, because enabling it there makes the whole test suite fail to link. Just use cargo test and maturin develop as separate commands and it takes care of itself.

2. Describe the experiment

Two front ends, and they converge before anything is parsed — so neither can accept a configuration the other would reject. Pick whichever suits you.

As a file

Copy config.example.toml from the repository root, or start from this:

population_size = 200        # individuals in the population
network_size    = 100        # nodes in every graph GET builds
crossover_rate  = 0.9        # 90% of selected pairs recombine
mutation_rate   = 0.2        # 20% of children mutate at all

[evolution]
type            = "generational"   # replace the whole population each round
num_generations = 500
elite_count     = 1                # carry the single best forward untouched

[selection]
type            = "tournament"
tournament_size = 5                # 5 entrants per tournament

[genome]
type        = "edge_edit"          # a script of edge edits
gene_length = 256                  # 256 edits per individual

[fitness]
type           = "epi_spread"      # maximise how far the epidemic reaches
infection_rate = 0.05              # per-edge, per-timestep
num_epidemics  = 30                # average over 30 outbreaks per evaluation
The top-level keys must come before the first [section] header. That is a plain TOML rule: once a table opens, every following key belongs to it. A population_size written below [evolution] silently becomes evolution.population_size, and the error you get complains that population_size is missing.

Or as Python objects

import get

config = get.Config(
    evolution       = get.EvolutionConfig.Generational(num_generations=500, elite_count=1),
    population_size = 200,
    network_size    = 100,
    crossover_rate  = 0.9,
    mutation_rate   = 0.2,
    selection       = get.SelectionConfig.Tournament(tournament_size=5),
    genome          = get.GenomeConfig.EdgeEdit(gene_length=256),
    fitness         = get.FitnessConfig.EpiSpread(
        sir = get.SirParams(infection_rate=0.05, num_epidemics=30)
    ),
)

The repository ships examples/config_builder.py, which covers all four objectives, both genomes and both strategies with this API.

3. Run it

import get

evolver = get.GraphEvolver("experiment.toml")     # or .from_config(config)

result = evolver.run(20260812)                    # one master seed drives everything
edges = result.best_edges

print("fitness:", result.best_fitness)            # in your objective's units
print("edges:  ", len(edges))
print(edges[:5])                                  # [(0, 3, 1), (0, 7, 1), ...]

run returns everything the run produced. best_edges is the best network found, as (u, v, multiplicity) triples with u < v; pairs with no edge are not listed. The seed reproduces the entire run — same seed and same config, same answer, on any machine.

4. Read the result

best_fitness is in your units: infected nodes for epi_spread, an RMSE for epi_prof_match. GET minimizes internally and converts back on the way out, so you never see a negated number — the whole scheme is here.

result.history is the convergence log, one row per generation, and result.best_genome_repr is the winning genome printed. Nothing is stored on the evolver, so a second run cannot be confused with the first.

The edge list drops straight into the usual tools:

import networkx as nx

g = nx.Graph()
g.add_nodes_from(range(100))                      # keep isolated nodes
g.add_weighted_edges_from(edges)

print(nx.number_of_edges(g), nx.average_clustering(g))
Write the config next to the results. config.to_toml() returns the exact document Rust parsed. Store it with the seed and the run reproduces verbatim — that pair is your whole provenance record.

What to change first

If you want…Change
A run that finishes faster num_epidemics down. It dominates run time — and raises the noise in every fitness number, so do not go far.
Less noisy fitness num_epidemics up. See Performance.
Stronger selection pressuretournament_size up.
More exploration mutation_rate or max_mutations up — they mean different things, see Crossover & Mutation.
Networks built from scratch rather than edited [genome] type = "sda". See Genomes.
To match a real epidemic curve [fitness] type = "epi_prof_match" plus a target_profile.
Your own scoring function Add an Objective.

Things that will confuse you once

  • An edge-edit run looks like it does nothing at first. Five of the nine operations need existing structure to work on, and a run currently starts from an empty graph, so Add and Toggle have to build something before the rest can do anything. Self-correcting, not a bug — see the operations.
  • Probabilities are not range-checked. A mutation_rate of 2.0 runs happily.
  • Two error messages name the wrong field — num_states = 0 reports as init_state, and population_size = 0 reports as elite_count or tournament_size. See Troubleshooting.
