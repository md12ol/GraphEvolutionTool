Extending GET

Add a Replacement Policy

Choosing which members of a scope a breeding event's children overwrite. Three steps — the shortest chain in GET — and the only one that belongs to a single strategy.

This axis is steady-state's alone. Generational rebuilds its whole population every iteration and never asks who to overwrite, so a reader extending that strategy has no step in this chain to take. Every marker says so on the line — ADD A REPLACEMENT STEP 2 (for SteadyState) — so a grep across all the chains at once does not hand you a step that is not yours.

The One Question a Policy Answers

A policy is handed the scope a breeding event drew and the fitnesses of everyone in it, and returns which positions the children take. It is the counterpart to selection: that answers who breeds, this who dies, and both work inside the same slice. Keeping them apart is what lets any selection scheme pair with any policy — a scheme no longer has to supply a replacement draw it has no theory for.

A policy consumes no randomness. Every one reads the scope's fitnesses and nothing else, so a replacement choice cannot shift a seeded run's stream. Keep it that way: a policy that draws would make every run before it irreproducible against every run after it.

Self-Elitism Rests Here

Worst takes the scope's least fit members, never its best. That is what makes steady-state self-elitist — and note it is a property of the policy, not of the selection scheme, which is why it holds whichever scheme picked the parents. A policy that can overwrite the best individual in a scope gives that guarantee up, deliberately or not.

What the User Ends Up Writing

[evolution]
type              = "steady_state"
num_mating_events = 5000
replacement       = { type = "random" }

It is read from the strategy's own table rather than a section of its own, because it belongs to whichever strategy displaces individuals — the same way elite_count belongs to generational. Absent means worst.

The Three Steps

git grep -n "ADD A REPLACEMENT STEP" get/src
StepWhereWhat
1get/src/evolver/replacement.rs:46 the variant, and any parameters it needs
2get/src/evolver/replacement.rs:77 the arm naming who the children overwrite; the match is exhaustive
3get/src/config.rs:163, get/src/dispatch.rs:958, get/src/py_config.rs:243 and :857 what a user names under replacement, the arm building it, and the Python mirror

Step 3 is one step across four sites rather than four steps, because none of them is a decision — once the variant and its arm exist, the rest is naming it in each of the three places a name can arrive from. The Python half is optional; leaving it out makes the policy TOML-only.

The Limit Worth Knowing Before You Start

A policy can only read what the engine records per individual. Today that is a genome and a fitness — nothing else. So Oldest, or anything keyed on lineage, tenure or distance from a parent, is not a variant plus an arm: it needs that quantity recorded first, which is a change to the engine rather than to this enum. Check what you need exists before writing the variant.
