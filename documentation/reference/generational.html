Reference

evolver/generational.rs

The generational strategy: replace the whole population every generation, carrying a configurable number of elites forward unchanged, and rescore everyone each time. This is the precise companion to Evolution strategies — read that first if you want the concepts rather than the call sequence.

Generational works in whole batches. Each generation it builds an entirely new population of the same size out of the old one, then scores every member of it. The alternative approach — change two individuals at a time and leave the rest alone — is evolver/steady_state.rs. The machinery both share (selection, the scoring gate, the mutation helper, the log row) lives in evolver/common.rs.

The loop, step by step

Every step below names the real function that performs it. Nothing else happens in between.

  1. Construct — Evolver::new (generational.rs:140). Assert elite_count < population.len(). Store the two contexts and the population; start with an empty history.
  2. Seed the random number generator — ChaCha8Rng::seed_from_u64(seed) (generational.rs:187), the first line of run. Every random choice for the entire run comes from this one generator.
  3. Score the starting population — common::express_and_score (generational.rs:192-193). This returns two parallel vectors: the expressed graphs, and their fitnesses already oriented so lower is better. Both are kept in local variables and reused.
  4. Clear the history and log generation 0 — self.history.push(generation_stats(0, &fitnesses)) (generational.rs:195-196). The clear() means calling run twice on one evolver does not stack two runs' logs together.
  5. For each generation from 1 to num_generations (generational.rs:198):
    1. Build the next population — advance_generation (generational.rs:199), which is steps 5a–5d below.
    2. Copy the elites forward (generational.rs:51-57). Only if elite_count > 0: list every slot index, sort those indices with common::rank — the same comparator selection uses, so "best" means one thing engine-wide — and clone the first elite_count of them into the new population unchanged.
    3. Breed until the new population is full (generational.rs:62-96). Each pass through the loop:
      • Selection::select(&population, fitnesses, 2, rng) picks two parents, with replacement — so the "pair" can be one individual and its own clone.
      • One crossover roll for the pair: rng.random_bool(crossover_rate), and if it passes, first.crossover(&mut second, rng) (generational.rs:73-75). Crossover recombines in place, leaving one child in each parent.
      • common::mutate_child on the first child, then on the second (generational.rs:76-87) — the two mutation rolls, in that fixed order.
      • Push the first child; push the second only if there is still room.
    4. Install the new population — self.population = next (generational.rs:98). The previous generation is dropped wholesale.
    5. Rescore the entire new population — common::express_and_score again (generational.rs:201-203), overwriting both the graphs and the fitnesses. Everyone is rescored, elites included.
    6. Log the generation — self.history.push(generation_stats(generation, &fitnesses)) (generational.rs:205).
  6. Report — self.outcome(graphs, &fitnesses, fitness.direction()) (generational.rs:208). Find the winner with common::best_index, clone its genome, move its graph out of the final scoring pass, record its fitness and the direction, and take the history. 
score ─→ log(0) ─→ ┌─ advance ─→ score ─→ log(g) ─┐ ─→ outcome
                   └────── × num_generations ─────┘

So a run performs num_generations + 1 scoring passes, and the history has num_generations + 1 rows.

The rules worth knowing

Elites are copied forward — and rescored anyway

An elite is one of the elite_count best individuals of the current generation, copied into the next generation without crossover and without mutation. It is the simplest possible insurance against losing a good solution to bad luck.

But being copied forward is not the same as being exempt from scoring. Every individual is scored fresh each generation, elites included (generational.rs:201). Under a stochastic objective — which the SIR objectives are, since each evaluation runs new epidemics — this means an elite's recorded fitness moves between generations while its genome does not.

That is correct, not a bug. The new number is a fresh sample of the same individual. Freezing the old score instead would let one lucky draw persist for the rest of the run, and selection would then be chasing that luck rather than the graph. See Fitness & orientation for what "stochastic objective" means here.

Two further points that surprise people. Elites are still eligible as parents — elitism copies them forward, it does not remove them from the mating pool. And elite_count = 0 is a legal configuration: the sort is skipped entirely and the run is genuinely non-elitist, which means the best individual really can be lost. That is a true property of a non-elitist genetic algorithm rather than a reporting defect — see what "the best" means below.

The odd slot count

Crossover produces two children, but the number of slots left to fill, population_size − elite_count, may be odd. When it is, the last breeding pass contributes one child and the other is discarded (generational.rs:92-95). Only ever the final pass is affected.

Both children are always bred, even when one is about to be thrown away. That keeps the cost in random numbers identical for every pass regardless of parity, which is what stops the random stream depending on whether the fill count happened to be even. It is a deliberate trade of a tiny amount of wasted work for a reproducibility property.

What "the best" means in the result

The reported winner is the best of the final population — not a running best carried across generations, and this is the same rule steady-state uses, so the two strategies agree with each other.

There are two reasons this is the honest number. Fitness is stochastic between batches, so a running best would substantially be a record of which generation drew the luckiest sample — which is the same argument that says an elite's old score must not be frozen. And at elite_count = 0 a non-elitist run genuinely can end without its best-ever individual: the run really did end without it, and a report claiming otherwise would be describing a population that no longer exists. At elite_count = 0 the divergence is a property of your configuration, not of the report.

Logging cadence

One row per generation, plus a row for the starting population. The initial population is logged as generation 0 before any breeding happens (generational.rs:196), which matches steady-state's iteration-0 row so the two strategies' histories share an axis — and means a run of zero generations still says where it began rather than producing nothing at all. 

history.len() == num_generations + 1
iterations:       0, 1, 2, 3, …, num_generations
What exists today. The rows are built correctly and travel out on EvolutionOutcome::history, which a Rust caller of Evolver::run reads directly. The Python boundary (dispatch::erase, get/src/dispatch.rs:411) converts each row's two fitness columns out of engine orientation and carries the whole log out on the result object, so a config-driven run can read its own convergence log. The ci_95 column and the per-row seed and run index described in Logs & results are still not fields on GenerationStats yet. See Status.

Randomness and reproducibility

run builds a ChaCha8Rng from the seed argument (generational.rs:187). It is explicitly not StdRng, whose algorithm is permitted to change between rand releases — which would silently break the reproducibility the seed parameter exists to provide.

Randomness is consumed only on the sequential path: the selection draws, the crossover roll, and the two mutation rolls per child. Expression runs in parallel across rayon workers but reads no randomness at all, so worker scheduling can never perturb a run. Per breeding pass the cost is 2 × tournament_size index draws, one crossover roll, and up to two rate rolls and two count rolls.

The evolver's seed is not the whole story under a stochastic objective. An SIR objective carries its own run seed and an atomic batch counter, and that counter advances once per call into express_and_score — which for generational is once per generation. That is what makes generational the fair comparison: every individual in a generation faces the same epidemic dice. Steady-state advances the same counter once per mating event, which is a very different rate. See Seeds & reproducibility.

A small run, narrated

Population of 6, elite_count = 2, num_generations = 2, crossover_rate = 0.0, mutation_rate = 1.0, max_mutations = 1, tournament_size = 3. To keep the arithmetic visible, imagine a toy genome that is just a number v, expressing to a graph with v + 1 nodes; one mutation adds 100; the objective minimizes the node count. So fitness is v + 1, and smaller is better. Starting values, deliberately unsorted: [5, 3, 9, 1, 7, 2].

  1. Score generation 0. All six express in parallel; node counts are [6, 4, 10, 2, 8, 3]. The objective minimizes, so orientation is the identity and the engine's numbers are the same numbers. No NaN, so the gate passes.
  2. Log row 0. best = 2.0; mean = 33 / 6 = 5.5; the squared deviations sum to 47.5, so the population variance is 47.5 / 6 ≈ 7.92 and std_dev ≈ 2.81. Row: { iteration: 0, best_fitness: 2.0, mean_fitness: 5.5, std_dev: 2.81 }.
  3. Generation 1 — elites. Sorting the slots by fitness gives slot 3 (f = 2), slot 5 (f = 3), slot 1 (f = 4), slot 0 (f = 6), slot 4 (f = 8), slot 2 (f = 10). The best two are copied unchanged, so the new population starts as [1, 2] — note these are the individuals with values 1 and 2, taken from slots 3 and 5, not the first two slots.
  4. Generation 1 — breeding pass. Two size-3 tournaments run. Say the first draws slots {4, 3, 0} with fitnesses 8, 2, 6 — slot 3 wins. The second draws {5, 5, 2} with fitnesses 3, 3, 10 — slot 5 wins (and note it was drawn twice, which with-replacement sampling permits). The crossover roll fails, because the rate is 0. Each child then mutates once, adding 100, giving values 101 and 102. Both are pushed.
  5. Generation 1 — second pass fills the last two slots the same way. The population is now six individuals: two untouched elites and four mutated children.
  6. Rescore. All six are expressed and scored again, elites included. Under this deterministic objective the elites' numbers do not move (2.0 and 3.0); under an SIR objective they would. The children score around 102 and up, because mutation made them much worse.
  7. Log row 1. best is still 2.0 — the elite survived — while the mean has jumped to roughly 70 and the deviation is large. Because elite_count ≥ 1 and this objective is deterministic, best_fitness can never worsen from one row to the next.
  8. Generation 2 repeats the same three steps and logs row 2.
  9. Outcome. best_index over the final fitnesses names the elite with value 1. Its graph is moved out of the final scoring pass — never re-expressed — and the result is: best genome value 1, a 2-node graph, best_fitness_engine = 2.0, direction = Minimize, and three history rows.

This example makes mutation strictly harmful so the mechanics are visible. In a real run mutation is a small perturbation that sometimes helps, and the mean fitness falls over time rather than exploding.

Costs and when to choose it

PropertyGenerational
Evaluations per iterationpopulation_size
Parallelism during scoringthe whole population at once — as wide as your cores
Python objective costone FFI crossing per generation
Are old scores ever stale?No. Everyone is rescored every generation
Elitismexplicit, via elite_count; can be switched off
Selection samplingwith replacement, so self-mating is possible

Prefer generational when the objective is stochastic and the comparison needs to be fair — every individual in a generation is scored under the same dice, which is exactly the guarantee steady-state cannot offer. Prefer it too when scoring is expensive and parallel, since a whole population of work is the widest unit the engine ever hands to rayon. The trade is that a generation is a barrier: it costs as long as its slowest individual.
