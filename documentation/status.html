Implementation status

This site documents GET as its design specifies it, which means a few pages describe things that are agreed but not yet in the code. Everything of that kind is listed here, in one table, with what exists today instead.

Why the site is written this way. The repository's design document is the authority on how GET works — where it and the code disagree, the design is the intent and the code is what has not caught up. So the pages are written in the present tense throughout, and anything not yet built carries a planned badge and a violet callout naming the current behaviour. This page is the index of those badges.

Designed, not yet built

Every planned badge on this site refers to one of these.

FeatureWhat the design saysWhat happens today Where it is documented
Replicate runs run takes a run count and returns a list of results, one per replicate. The master seed feeds a stream whose draw i is run i's seed. run(seed) performs exactly one run. Looping in Python works, but you choose the seeds yourself and lose the stream property — so record them. Python API · Reproducibility
max_cores, and the per-call thread pool One cap governing both replicate-level and population-level concurrency, with the pool built per call rather than globally. No cap and no pool construction. Parallelism uses the default global pool. Performance & Memory
ci_95, and the per-row seed and run index Five log columns plus the two provenance columns that let replicate logs be concatenated and still separated. Four columns: iteration, best_fitness, mean_fitness, std_dev. Logs & Results
save_logs / save_results Write the convergence CSV, and the best individual alongside the generated TOML as the provenance record. Both raise. Logs & Results · lib.rs
Supplying a base graph A setter taking the node count and an edge list, so an SDA result can be refined by an edge-edit run with no new data format. Three checks come with it — node count match, cap-narrowing rejection, and the empty-graph default. There is no setter. Every edge-edit run starts from an empty graph, which leaves five of the nine operations inert until Add/Toggle build structure. Python API · Configuration

Deliberately not built

These are decisions rather than gaps, and they are documented so their absence reads as intentional. Reasoning on Design Notes.

Not in GETBecause
Multi-objective optimization One f64 per individual. The batched, pymoo-shaped interface is about the call signature, not about Pareto fronts.
Convergence detection or early stopping A run ends after its configured generations or mating events. Fixed-length runs, deliberately.
Variable-length genomes Dimensions are set once per run. Crossover tolerates unequal lengths defensively, but nothing produces them.
Random immigrants or restarts They would require putting genome-minting capability back into the engine, which the design deliberately removes.
Variable node countEvery graph in a run has network_size nodes.
Island models or migrationOne population.
A second crossover operator per representation Wanted, but sequenced after the rest of the design. Until a second operator exists there is nothing to select between, so no config field is built for it. This one is a "not yet", not a "never".

Where the code is ahead of the design document

The reverse case also exists, and this site documents the code in these places, with no badge. Noting them here so a reader who checks the design document and finds a contradiction knows which way it runs:

  • The design's status table still describes the Python interface as built "except dispatch", with run unimplemented. run is fully implemented and all four strategy × genome dispatch arms are tested end to end.
  • The design's closing section still lists the one-mutation contract with max_mutations and the cap-derived SDA alphabet as decided but not yet true of the code. Both are now true.

Both are stale status claims rather than design changes, and correcting them is an owner's call at a joint meeting — see documentation/README.md for the full list of things the design document should hear about.
