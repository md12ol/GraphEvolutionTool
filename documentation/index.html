Graph Evolution Tool

Evolve Networks Against an Objective

GET searches for graphs that score well on a measure you choose — how far a simulated epidemic spreads, how closely a network's structure matches a reference set, or any objective you write yourself in Python or Rust. You describe the experiment in a config file or in Python; GET runs an evolutionary algorithm in Rust and hands back the best network it found, plus the convergence log that produced it.

What It Produces

The Idea in One Picture

Everything in GET is a loop around four things. A genome is a compact recipe. Expressing it produces a graph. Scoring that graph produces a fitness number. An evolver uses those numbers to decide which genomes get to have children, and the loop goes round again.

What You Get to Choose

AxisOptionsWhere
Representation edge-edit — a script of edits over a starting graph · SDA — an automaton that writes a graph from scratch [genome] type
Strategy generational — replace everyone each round · steady-state — one mating at a time [evolution] type
Objective epi_spread · epi_length · epi_prof_match · struct_match · or your own, in Python or Rust [fitness] type
Scope Which slice of the population one breeding event may touch — global · random_subset [scope] type
Selection Which of that slice become parents — tournament · best [selection] type
Replacement Which of that slice the children overwrite — worst [evolution] replacement
Crossover Applies to whichever representation is running — two_point [crossover] type
Mutation Chosen per genome, because the two representations' mutations share no shape [genome] mutation

The three axes of a breeding event — scope, selection and replacement — are independent, and every combination is legal. Variation & Selection has what each one decides.

A Complete Run

import get

config = get.Config(
    evolution       = get.EvolutionConfig.Generational(num_generations=500, elite_count=1),
    population_size = 200,
    network_size    = 100,
    crossover_rate  = 0.9,
    mutation_rate   = 0.2,
    scope           = get.ScopeConfig.Global(),
    selection       = get.SelectionConfig.Tournament(tournament_size=5),
    genome          = get.GenomeConfig.EdgeEdit(gene_length=256),
    fitness         = get.FitnessConfig.EpiSpread(
        sir = get.SirParams(infection_rate=0.5, num_epidemics=30)
    ),
)

evolver = get.GraphEvolver.from_config(config)
results = evolver.run(seed=20260812)   # one master seed drives everything
result  = results[0]                   # run() always returns a list, one entry per replicate

print(result.best_fitness)             # nodes infected, in your units
print(len(result.best_edges))          # the winning network, as (u, v, weight) triples
print(len(result.history))             # the convergence log, one row per generation

result.save_logs("convergence.csv")    # iteration, best, mean, std_dev, ci_95, seed, run_index
result.save_results("results.txt")     # best individual, with the run's config TOML alongside
That infection_rate is high on purpose. At 0.05 an outbreak on a sparse 100-node graph dies almost immediately whatever the topology, so every individual scores alike and selection has no gradient to follow. The same value is used by config.example.toml and examples/config_builder.py.

Getting Started

Pick the route that matches how you want to drive GET — the four route cards above are one page each, written to be read alone and carrying the complete worked example for that route. Whichever you choose, the same experiment is expressible in the others: the Python configuration objects serialize to TOML and that is what Rust parses, so neither front end can accept a configuration the other would reject, and the generated TOML doubles as the provenance record of a run.
